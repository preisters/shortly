# 최종 검수 후 내보내기 안전성 보완

2026-09-07. 기존 작업물·환경 설정·API 키를 변경하지 않았으며 유료 API 호출, 실제 CapCut 프로젝트 수정, 서버 재시작, 커밋/푸시는 실행하지 않았다. 검증은 격리한 임시 파일·DB·프로젝트와 가짜 공급자 응답으로 수행했다.

## 수정 사항

1. **TTS 누락 차단**: 제목/본문 음성 생성 실패, 음성 파일 누락, 오디오 소재 연결 실패를 성공으로 반환하지 않는다. 사용자가 TTS를 비활성화한 경우의 무음 내보내기는 유지한다.
2. **가이드-에셋 결합 검증**: 준비 시 원본 가이드 해시와 명세의 해시를 대조한다. 커밋 때 선택/유형/고지 정보, TTS 설정, 선택 에셋과 본문 음성 파일 해시를 다시 검사한다. 변경됐으면 재준비를 요청한다.
3. **본문 타이밍 동결**: 준비 시 실제 TTS 또는 TTS 미사용 시 동일한 대사 길이 추정기로 최종 본문 계획을 계산한다. 그 계획으로 영상 길이를 검증한다. 커밋은 저장된 본문 계획을 사용하며 제목·시작음 뒤로 전체를 이동할 뿐 본문을 재생성/재추정하지 않는다. 4초 영상보다 긴 컷은 준비 단계에서 거부한다. 자동 반복이나 재생성은 하지 않는다.
4. **완성 후 게시**: 템플릿 기반 내보내기는 CapCut 목록 디렉터리 밖의 `.shortly-staging`에서 제작한다. 성공 및 개인판 검증 통과 후 최종 폴더로 이동·목록 등록한다. 예외나 검증 실패 시 임시 복사본을 정리하며 기존 편집본은 덮어쓰지 않는다. 프로세스 강제 종료/정전 때 임시 폴더가 남을 가능성은 있지만 CapCut 완성 프로젝트 목록 밖이다. 목록 등록만 실패하면 완성된 프로젝트 경로와 경고를 반환한다.
5. **생성 구도 일치**: 영상 생성 프롬프트의 상단 30% 비우기 지시를 없앴다. 이미지와 마찬가지로 전체 프레임을 자막 아래 표시 영역에 넣는 정책을 사용한다.
6. **조사 항목 누락 방지**: 필수 내용 8개와 추가 조사 5개를 모두 검색어로 유지한다. 검색어 예산은 자동 추가 검색어만 제한한다. 검색 실행 자체가 출처 확보/내용 검증 성공을 뜻하지는 않는다.
7. **구형 레이아웃 호환**: 구형 내보내기에 명시적인 `layout.image`가 전달되면 기존 위치·배율을 존중한다. 전달되지 않은 경우 새 원본 보존 기본 배치를 사용한다.
8. **UI 승인·무효화**: 준비 시 TTS 비용 가능성을 안내하고 승인을 요청한다. API도 TTS 활성 상태에서는 승인을 요구한다. 입력/명세 변경 시 준비 결과를 해제하고 중복 버튼 실행을 막는다. 서버는 별도로 저장 상태를 재검증한다.

## 동작 변경과 사용법

- **기존 내보내기 준비 결과는 재사용하지 않는다.** 새 준비 결과는 버전 2이며 본문 계획·검증 정보를 포함한다. 기존 가이드와 선택 에셋을 복구/재생성할 필요는 없고, 페이지에서 준비만 다시 실행하면 된다.
- 준비 단계에서 TTS가 활성화되어 있고 캐시가 없으면 승인 후 유료 합성이 발생할 수 있다. 이미 있는 음성은 재사용한다. 실패한 준비에서 생성된 음성 캐시도 보존한다.
- 제목 TTS는 커밋에서 필요할 때 생성한다. 커밋 확인문에도 비용 가능성을 안내한다. 본문 TTS는 준비 때 확정한 파일을 사용한다.
- ffprobe로 영상 길이를 읽지 못하면 개인판 준비를 중단하고 설치/파일 확인을 요청한다. 길이를 모르는 영상을 안전하다고 간주하지 않는다.
- 실패한 커밋은 완성본으로 공개하지 않으며, 가이드/에셋/음성은 유지하므로 원인을 해결하고 다시 준비할 수 있다.

## 검증 결과

- 현재 서버와 동일한 Python 3.11.9 환경: **248개 테스트 전부 통과, 실패·오류·건너뜀 0개**.
- 외부 연결을 차단하되 Windows 비동기 이벤트 루프의 내부 socketpair만 허용했다. 실제 LLM/TTS/이미지/영상 생성이나 로컬 모델 기동은 실행하지 않았다.
- 임시 프로젝트에서 준비→저장/로드→커밋→경로 재연결→검증 성공을 확인했다.
- 제목 TTS 실패, 본문 TTS 실패, 음성 파일 소실, 선택/파일/설정 변경, 대본 불일치, 영상 길이 부족, 중간 오류, 검증 실패에서 게시 차단을 확인했다.
- 성공한 TTS 경로에서는 커밋이 본문을 재합성하지 않고 제목만 합성하는 것을 가짜 공급자로 확인했다.
- HTTP 테스트에서 준비 승인 요구와 커밋의 명세 저장소 전달을 확인했다.
- Node 기반 UI 모의 실행으로 승인→준비→커밋 및 입력 변경 시 준비 무효화를 확인했다. JavaScript 구문 검사와 Git diff 공백 검사도 통과했다.

실제 CapCut 렌더와 실제 상용 모델 생성은 아직 미실행이다. 서버 재시작 후 페이지를 새로고침하고 준비부터 다시 실행해 새 프로젝트의 구도·음성·자막을 확인한다. 이전 프레임 보완의 남은 범위(컷별 구도 편집, 채널별 별도 표시 영역 설정, PDF 본문 읽기, 렌더 프레임 시각 검수)는 그대로 후속 작업이다.
