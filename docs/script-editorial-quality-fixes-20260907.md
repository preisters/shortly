# 대본 의도 보존 및 의미 검수 보강

작성일: 2026-09-07. 이번 변경은 생성 파이프라인에 적용되며 기존 저장 대본·학습 데이터·CapCut 프로젝트는 수정하지 않았다.

## 수정 사항

| 영역 | 적용 내용 |
| --- | --- |
| 제작 의도 | 신규/수정 대본과 후속 흐름 보정에 원래 주제, 최신 수정 요청, 필수/선택 내용을 전달한다. 팩트체크 입력에서도 사용자 지시와 대본을 중간에서 자르지 않는다. |
| 제목 | 따옴표로 명시한 제목을 일반 훅 선호 규칙보다 우선해 유지한다. 최신 제목 변경 지시는 이전 제목보다 우선한다. |
| 분량 | 명시한 영상 분량 범위(예: 38~42초)를 가이드와 같은 계산식으로 비교해 보정에 전달한다. 범위 밖이면 완료 후에도 경고를 남긴다. 실제 TTS 길이가 아닌 예상값이다. |
| 입력 항목 | 추가 조사 5개, 필수 내용 8개 및 항목별 길이의 조용한 잘림을 제거했다. 검색어 자체는 검색에 적합하게 줄이되 원문 항목은 보존한다. |
| 선택 내용 | '분량이 허용된다면', '선택 사항', '가능하면' 등으로 표시된 내용은 생략만으로 필수 누락 실패를 만들지 않는다. 포함했을 때의 사실 검증은 여전히 필요하다. |
| 조사 출처 | 동일 출처가 여러 질문에 걸린 이력을 보존한다. 주체명 없는 필수 항목 자료도 보호하고, 결과 순위 제한 전에 명시한 질문별 자료를 우선 확보한다. 조사 요약에 후반 스니펫이 통째로 잘리지 않게 했다. 검색 실패나 자료 부재까지 해소한다는 뜻은 아니다. |
| 보정 제한 | 비트 개수와 연결어 시작 횟수만으로 실패시키지 않는다. 새 연결어/주장 키워드 또는 수치 생략이 생긴 보정안은 의미 보존 검사로 오탐을 해소한다. 새로운 숫자 추가·치환은 계속 거부한다. 의미 검사 실패/형식 오류도 보수적으로 거부한다. |
| 의미 검수 | 입력 의도, 제목·도입, 이야기 전개, 결말 보상, 정보 밀도를 별도 검사한다. 각 판정에는 구체적 이유가 필요하다. |
| 보완 한도 | 의미 검수에서 문제를 찾으면 그 지적을 반영하는 보완을 최대 한 번 시도하고, 실제 대본이 바뀌면 재검수한다. 계속 실패하면 경고를 남기고 루프를 돌지 않는다. 기존 규칙 기반 보정은 별도로 유지한다. |
| 결과 표시 | 의미 검수를 못 했거나 응답 형식이 틀리면 전체 품질 통과로 표시하지 않는다. 구형 저장 가이드의 규칙 점검만으로 의미 검수 완료를 주장하지 않는다. |
| 제작 가이드 | 정제된 스타일 지침을 사용한다. 78% 화면 점유율, 학습 영상의 전환 횟수, 긴 쉼표 문장 강제, 명확한 종결 금지 등 오래된 출력 지침을 제거했다. |

## 변경 파일

- `shortly/generate/editorial.py` (신규): 입력 계약 보조 함수, 분량 검사, 의미 검수, 사실 의미 보존 검사.
- `shortly/generate/script_gen.py`: 생성/수정 컨텍스트 전달, 제목 보존, 보정 제한과 필수/선택 처리.
- `shortly/generate/research.py`: 항목 보존, 질문별 출처 이력 및 결과 선택, 요약 입력.
- `shortly/generate/factcheck.py`: 전체 사용자 의도·대본 전달, 재시도 입력 보존.
- `shortly/generate/guide.py`: 정제된 출력 노트.
- `shortly/service.py`: 최종 의미 검수·한 번의 보완·재검수와 품질 메타데이터.
- `shortly/web/static/app.js`, `index.html`: 결과 경고 및 입력 안내.
- `tests/test_editorial_contract.py` (신규), `tests/test_framing_regressions.py`: 회귀 검증.

## 검증

- 실제 서버 환경의 Python 3.11.9로 전체 테스트 **270개 통과**, 실패·오류·건너뜀 0개.
- 외부 소켓 연결 차단 상태로 테스트했다. 비동기 테스트 런타임의 내부 socketpair만 허용했다.
- 새 검증 22개: 원문 항목 보존, 고정 제목, 최신 제목 요청 우선, 선택 누락, 4/10비트 허용, 의미 검수 응답 검증, 무한 보완 방지, 잘못된 인과 차단, 정상 연결 개선, 분량과 조리 시간 구별, 출처 이력, 후반 조사 자료 유지, 출력 노트 정제 등.
- 프런트엔드 JavaScript 구문 검사 통과.
- 실제 상용 모델 호출, 웹 검색, TTS·에셋 생성, 저장 가이드 재생성은 실행하지 않았다.

## 비용과 한계

- 다음 실제 생성/수정부터 기존 생성 모델로 의미 검수 호출이 추가된다. 정상 경로는 1회(출력 상한 1,600토큰), 문제 발생 시 보완 1회와 재검수 1회가 추가될 수 있다. 어휘 기반 사실 변경 의심이 있으면 보정당 짧은 의미 보존 검사 1회(출력 상한 600토큰)가 추가된다. 이는 실제 소비량/가격이 아니라 호출별 설정 상한이다.
- 항목을 많이 입력하면 검색 횟수와 모델 입력량도 증가한다. UI에 이를 안내한다. 입력을 조용히 버리는 방식으로 비용을 줄이지 않는다.
- 의미 검수도 LLM 판단이므로 조회수·흥미·사실 정확성을 보장하지 않는다. 별도의 인터넷 팩트 조사나 독립 모델 교차 검증을 새로 수행하는 기능은 아니다.
- 따옴표 없는 자유 형식 제목·도입·결말 요구는 원문 전달 및 의미 검수로 보호한다. 모든 자연어 지시를 코드가 축자 계약으로 해석하지는 않는다.
- 정규식/어휘 기반 필수 내용 검사는 아직 완전한 의미 일치 판정이 아니다. 표현이 달라진 경우 오탐이 남을 수 있으므로 경고와 실제 대본을 함께 확인해야 한다.
- 목표 분량과 필수 내용이 양립 불가능하면 전부 충족한 것처럼 표시하지 않는다. 경고를 확인해 선택 내용을 줄이거나 목표 길이를 조정해야 한다.

## 적용 방법 / 롤백

서버를 재시작하고 웹페이지를 새로고침한 뒤 신규 생성 또는 수정 요청에서 확인한다. 기존 저장 가이드는 자동 재생성하지 않는다. 특히 다음 불닭 가이드에서는 도입의 회수 조치, 후반 공식 재검사 결과, 사용자 지정 복귀 행사라는 결말이 유지되는지 사람이 확인해야 한다.

롤백 시 위 파일의 이번 변경만 되돌린다. 작업 트리에 기존 수정이 많으므로 파일 전체 되돌리기나 `git reset --hard`를 사용하지 않는다. 생성 데이터 삭제나 DB 마이그레이션은 필요하지 않다.
